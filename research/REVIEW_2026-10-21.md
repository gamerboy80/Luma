# Luma audit — October 21, 2026

Reviewed the current working tree, preserving earlier uncommitted changes. The review focused on native wallpaper restoration, library/import ownership, editor persistence, pending desktop playback, window reopening, SteamCMD and Wallper import paths, and the native scene-host boundary. The existing worker and renderer regressions were also run. This is a review of those paths, not a claim of complete compatibility or absence of all bugs.

## Confirmed issues fixed

| Issue | Effect before the fix | Resolution and regression evidence |
| --- | --- | --- |
| Native catalog cleanup after multiple installs | If the first install created the manifest and a later install replaced it, cleanup incorrectly reported that the catalog had changed. A simple match against any install would also be insufficient to preserve external edits made between installs. | Follow exact manifest hashes through each saved predecessor snapshot back to the install that created the manifest. A broken or incomplete chain retains the manifest and removes only Luma records. Temporary-catalog tests reproduced the original failure and now cover consecutive installs and an external edit between them. |
| Editor index changed outside the running store | Rename/create could overwrite newer `projects.json` contents; Clear Data could accept changed ownership records while the old editor was still running. | Capture the exact index bytes after load and successful save. Compare them before index writes, project lifecycle mutations, and cleanup. Refuse unsafe or oversized indexes. Preserve retrying cleanup with an unchanged valid index despite missing/malformed project content. A regression reproduced the stale rename overwrite and verifies that both the external index and project metadata remain intact. |
| Clear Data during an import | Wallper imports and overlapping import entry points were not reliably represented by the UI activity label. Cleanup could begin while a managed copy or metadata operation was still in flight. Cancelled synchronous imports could also publish an entry. | LibraryStore tracks every active import, including nested batch imports; both its cleanup preflight and AppModel refuse cleanup during imports/downloads. Check cancellation before starting and before publishing. Regressions check the full import lifetime, cleanup refusal, cancellation, and source preservation. |
| Playback state during pending loads | Pending videos continued playing under global pause, pending surfaces kept old volume/fit/scale settings, and reverting an edit could leave an obsolete replacement waiting to reveal under the same wallpaper ID. | Apply policy and configuration to pending surfaces, enforce policy on retries, and compare complete render identity when keeping/cancelling a replacement. A hidden AppKit/AVPlayer fixture verifies rate zero, updated settings, a ready first frame while paused, and cancellation of an obsolete replacement after a revert. |
| Open Library could focus Settings | The reopen helpers picked the first titled window, which could be Preferences or another panel. | Mark WindowGroup library windows with an explicit identifier and select only that role. AppKit tests verify that an earlier settings window and a changed display title cannot redirect library-window selection. |

Editor-test failures now print the assertion error to stderr and exit with status 1 instead of producing a top-level Swift trap.

Core media, scene, and build commands used host AVFoundation, WebKit/GPU, and Xcode compiler-plugin access. Previous restricted runs could not access those services; those environment failures were not counted as passes. The Release build's only warning was the expected skipped App Intents metadata extraction. No AVFoundation deprecation warning appeared.

## Limits of this verification

- The AppKit tests exercise role selection and real pending video state using invisible/hidden windows. They do not replace interactive verification of SwiftUI menu actions, Dock transitions, minimize/reopen, or login-item changes.
- Private SkyLight/Aerial behavior across lock, sleep, macOS updates, and restart still requires testing on the target Mac. This audit did not change the user's real wallpaper catalog or desktop-image settings.
- Authenticated SteamCMD downloads, arbitrary Workshop scene fidelity, and multiple physical displays were not exercised.
- No commit or push was made as part of this audit.
