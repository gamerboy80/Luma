# Luma source review — October 20, 2026

The review covered app startup and shutdown, single-instance coordination, library imports and deletion, Clear Data ownership, editor persistence and scene edits, native wallpaper receipts, and the native/JavaScript renderer boundary. Findings were based on the checked-in code and regression results.

## Fixed findings

| Area | Problem and fix |
| --- | --- |
| Startup | The duplicate-process check ran after writable services could be created, and two launches could both see another process and quit. The atomic OS lock now runs before `AppModel` construction; only the losing process exits. A six-process race checks this behavior. |
| Windowless shutdown | The delegate received its model only after the library view appeared. The app now attaches shutdown ownership from the app scene, and registers its reopen action through commands as well as the library view. |
| Library deletion | Removal trusted the passed wallpaper folder and deleted media even if saving the index failed. It now validates the stored UUID ownership record and path, preserves files on save failure, and retains the record on deletion failure. |
| Unsafe library state | Decodable but unsafe saved folder paths and duplicate IDs were accepted. Loaded and saved records are now validated; an invalid index is preserved and blocks further writes and cleanup until recovery. |
| Import trees | Hidden symlinks were excluded from validation but included in the subsequent recursive copy. Tree validation now includes hidden entries, rejects special files and symlinks, and reports traversal errors. |
| Import metadata | Non-finite video duration could prevent JSON encoding. It is now omitted. Direct downloads now supply their title to the specific import instead of renaming whichever wallpaper happens to be first after an asynchronous operation. |
| Editor index | A corrupt index could be overwritten, and failed create/import/duplicate saves left phantom entries and recent IDs in memory. Load failures now block writes; failed saves roll back those collections. Clear Data disables further store writes. |
| Editor saves | An open document could overwrite package changes made in Finder. Saving now checks the original scene bytes, validates project metadata before writing, and refuses an external conflict. Exporting into the source project is rejected. |
| Layer edits | Numeric ID increments could overflow; malformed IDs or layer arrays could reach mutable state. New IDs are bounded, IDs are checked, and candidate edits are validated before changing the scene or undo history. |
| SceneScript review | Relative source names were formed by slicing absolute paths, which fails for macOS `/var` and `/private/var` aliases. Traversal now constructs relative names from directory components and preserves incomplete-review errors. |
| SceneScript execution | Hook inspection referenced the deliberately hidden `Function` parameter, breaking ordinary reviewed text scripts. It now captures the intrinsic inside the SES compartment. Init-only text scripts are also accepted. SES isolation, source approval, bridge validation, and watchdogs remain active. |
| Failed script registration | Queued events were still sent after registration failed, causing a false timeout. Those events are now discarded for that script. |
| Renderer lifecycle | Ready was sent before the renderer handle was assigned and then sent again. The page now sends ready only after mount completes; stopped hosts reject later callbacks and clear their ready state. Top-level navigation is restricted to the renderer document. |
| Native wallpaper removal | Normal removal left `native-receipt.json` behind, making the install reappear after restart. Successful removal now deletes that receipt and includes its validated generated asset ID in cleanup. |
| Native selection and paths | The installed-selection backup was written after changing the system selection. Both backup sides are now written first. Native write paths reject symlinks, unknown removal schemas are rejected, and installation detects a catalog created while an absent catalog was being prepared. |
| Desktop stills | Replaced/restored stills could accumulate without ownership records, and later user wallpaper choices could be lost. Receipts now retain generated files through replacement, preserve a later user selection as the new baseline, and delete superseded owned files. Clear Data restores every display before deleting a shared still. Older receipt formats still decode. |
| Steam cancellation | Cancellation during an awaited import could still remove the downloaded source afterward. A successfully imported download is now retained if cancellation was requested during import. |
| Verification scripts | The editor test script omitted `WallperVideos.swift`, a dependency of `LibraryStore`. It now compiles from a clean checkout. |

## Verification

- `Scripts/test.sh`: 95 assertions passed, including generated video/HEVC encoding and native catalog installation/removal against a temporary catalog.
- `Scripts/test-editor.sh`: 38 checks passed, including index rollback/recovery and external scene conflict preservation.
- `Scripts/test-instance.sh`: one winner among six simultaneous processes, lock release after exit, and symlink rejection passed.
- `Scripts/test-scenes.sh`: packed-scene playback, editor bridge, seeking, frame capture, texture decoding, movie export, reviewed and init-only scripts, disabled/stale approval, syntax rejection, capability checks, and source/init/update infinite-loop watchdog checks.
- Standard and sandboxed Release builds succeeded. The normal app's signature was verified and `dist/Luma.zip` was packaged. Both Dock/single-instance plist keys were checked in the built app.
- Shell syntax, workflow/dependency YAML parsing, and `git diff --check` passed. Renderer changes were rebuilt from the pinned upstream commit and the checked-in patch.

The review used isolated temporary fixtures. It did not clear the user's library, change the real macOS wallpaper catalog, authenticate to Steam, register login items, or perform a live lock/unlock cycle. Private SkyLight behavior, interactive Dock transitions, physical multi-monitor recovery, and Steam account downloads still require manual checks. The review and automated suites do not establish full Wallpaper Engine compatibility or prove that all untrusted scripts are safe.

## Automation

The build-and-test workflow runs on main pushes, pull requests, and manual dispatch. It builds both profiles, packages each app, runs four independent test jobs, checks source syntax, and retains logs/artifacts for 14 days. Actions are pinned to immutable commits with read-only repository permissions. Dependabot proposes monthly action updates. CI execution itself must be observed on GitHub after the workflow is pushed; local YAML validation does not confirm a hosted runner's media or graphics capabilities.
