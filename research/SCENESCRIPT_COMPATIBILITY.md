# SceneScript compatibility, bridge limits, and isolation

Luma compares each declaration in the pinned official 2.8 SceneScript type file with the bundled WebWallGL renderer and the host/Worker bridge. The full per-global, per-event, per-class, per-property, and per-method classification is [SCENESCRIPT_API_COVERAGE.md](SCENESCRIPT_API_COVERAGE.md); the source declarations are [SCENESCRIPT_API_TYPES.d.ts](SCENESCRIPT_API_TYPES.d.ts). The upstream API is documented in the [SceneScript reference](https://docs.wallpaperengine.io/en/scene/scenescript/reference.html) and [definitions file](https://docs.wallpaperengine.io/reference/lib.sceneScript.d.ts).

“Implemented” in the matrix means that Luma has a functional path with the listed constraints. It does not promise exact Wallpaper Engine rendering. “External provider” means the API shape/event exists, but current values come from a real optional provider. “Unsupported” means use is surfaced as an error/diagnostic instead of returning a success-shaped value or no-op.

## Execution and bridge

- Scripts are evaluated inside SES compartments in a dedicated Worker, not in WebGL’s render thread. The Worker has no DOM, filesystem, native app bridge, network, IndexedDB, cache, Worker-spawning, or ambient timer/message capability exposed to scripts. Ordinary ECMAScript and compartment-local math/date values remain available.
- Host-side watchdogs run outside the Worker. Only one script event is in flight at a time; frame updates are coalesced/skipped while busy. A timed-out Worker is terminated, its timers and queued events are discarded, and scripts are disabled for that scene. The renderer retains its latest completed frame and continues responding to the app.
- The host sends bounded snapshots and receives typed patches/actions. Layer IDs are mapped to scene generation and live layer identity. The host validates field allowlists, types, vector dimensions, finite/ranged values, normalized project-relative paths, serialization size, command counts/rates, and current generation before applying a result. Unknown or stale commands are rejected with diagnostics.
- Limits cover script source, Worker messages/snapshots, layer count, nesting, timers, storage, commands, event queues, and per-frame updates. Browser Workers do not offer a portable enforceable heap quota; the timeout and bounded bridge reduce risk but cannot prove protection from every memory-exhaustion attack.
- Vectors and matrices created inside the compartment retain their methods. Layer vectors are live facades where the API is mutable, so component assignments such as `thisLayer.origin.x = 20` write through the same validated path as assigning a new vector. Nested layer references are reconstituted from the current layer snapshot and preserve that write-back behavior.
- SceneScript review and the execution toggle remain separate gates. Both must allow execution. Approval is fingerprinted to the wallpaper and reviewed script contents; a content change needs a new review. Disabling execution tears down the Worker and revokes active execution for that scene.

## Implemented API families

The exact signatures, individual classifications, and remaining limits are in the matrix. Functional families include:

- `Date`, `Date.now()`, `Math.random()`, `Vec2/3/4`, `Mat3/4`, `WEMath`, `WEVector`, and `WEColor`. A per-event wall-clock sample advances for `Date`, `Date.now()`, and engine time values. Math helpers and vector/matrix methods run in SES. Singular matrix inverses and invalid bridge values raise diagnostics/errors.
- `engine`, `input`, `thisScene`, `thisLayer`, `thisObject`, `console`, and `shared`. Scene/canvas/device values are snapshots; layer lookup, hierarchy, text, transforms, visibility, supported scene settings, and renderer actions route through typed bridge operations. Cursor data reflects Luma’s renderer/window interaction; Luma does not capture global mouse input from other applications.
- Text fields that WebWallGL renders: text, point size, font, color, background color/brightness/opacity, padding, horizontal/vertical alignment, anchor, width/row limits, ellipsis, alpha, spacing, and shadow. Script-written values update the renderer’s live text widget and are checked against the actual rendered frame in regression fixtures. A requested font must resolve in the wallpaper or the configured shared assets.
- Existing scene effects/material passes, material constants, timeline and puppet animation playback/frame state, image sprite animation, local sound/video decoder controls, and supported particle backend operations. Missing effects/material passes/animations/decoders/particle systems and unsupported callback methods produce diagnostics. Dynamic model geometry, bone transforms/physics, attachment matrices, native media control, and decoder completion callbacks are not bridged; see individual matrix rows.
- `localStorage` and `shared` operate in Worker memory. Storage is typed, capped at 100 KiB/256 keys per scene lifetime and cleared on destruction/rebuild; it is not persistent across app launches. Shared layer handles and helper functions remain live inside the Worker. Host shared snapshots include only bounded own data properties; serialization never invokes getters or reads unsupported API methods. This prevents a scene's shared playlist of layer handles from terminating unrelated clock/media scripts. `registerAsset` only accepts normalized relative paths in the active wallpaper. `openUserShortcut` and arbitrary process/file launching are rejected.

## Providers and unavailable data

The selected player's fixed query runs in a host-owned `/usr/bin/osascript` subprocess with an eight-second process deadline, bounded JSON output, and cancellation on source change or shutdown. It writes no script or metadata files. This keeps AppleScript off Luma's main thread without using `NSAppleScript` on a background thread. SceneScript cannot supply query source, arguments, or an application target.

- Media callbacks are connected to an actual opt-in Music or Spotify provider when selected in Luma settings and authorized by macOS. The host sends bounded title, artist, album, album artist, track index, playback state, duration, and position snapshots. No song is inferred from a layer name. With no provider or current item, script metadata fields are empty and a diagnostic identifies the missing provider; no placeholder metadata is fabricated. Artwork and lyrics are unavailable and are diagnosed. Timeline updates follow the selected provider’s polling cadence and permissions.
- `AudioBuffers` has the documented typed-array shape and receives Luma’s active wallpaper/BGM spectrum snapshot. If an optional live audio-capture provider is absent, Luma reports that limitation; disabled audio supplies silence. Values are snapshots, not mutable handles to a native audio device.
- User shortcut launch, global hotkeys, browser/system-wide input, RGB hardware, file/network access, and arbitrary application bridges are intentionally unavailable.

## Verification scope

The focused WebKit scene suite exercises text updates and style/component write-back through to rendered pixels, nested layer lookup/write-back, advancing dates, animation/media/audio/particle bridge shapes, diagnostics for absent providers and renderer capabilities, review/toggle gating, and initialization/update/timer loops. Malicious constructor/capability escape fixtures check that Worker scripts cannot recover browser capabilities. Native core/editor tests and app builds are run separately. Fixture-driven checks do not prove compatibility with every Workshop scene, GPU, WebKit version, codec, or macOS privacy configuration.
